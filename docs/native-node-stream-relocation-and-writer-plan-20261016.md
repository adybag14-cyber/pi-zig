## Planned file writer owner

The writer is a genuine Writable-derived native WriteStream. Its producer performs asynchronous open, actual partial write progress, optional fsync and close through the existing owner-thread Env IO hub and native `std.Io.Group.concurrent` workers. Regular-file `O_NONBLOCK` alone is insufficient, and synchronous file writes followed by an invented nextTick completion are not acceptable.

Native worker packets hold copied paths, copied byte buffers, exact native file ownership, positions, flags and completion tokens. They never access JS values or invoke guest callbacks. All JS roots stay with the VM owner. A successful write callback requires actual byte completion for the whole public chunk. `bytesWritten` records observed completed bytes; `pos` follows the original WriteStream submission policy. Open/ready, write callback, finish and close retain their distinct source ordering. `_destroy` waits for in-flight file IO before closing its exact file. It cannot close a still-used handle, manufacture producer EOF or signal a child.

The existing Env task pump converts all completion errors to Promise rejection. Stream callbacks need an additive opt-in path that propagates their exact callback exception out of the owner pump, preserving the default behavior of existing Promise tasks. This is separate from Root's shared SDK/Scope pending-exception repair; that repair is not duplicated here. File ownership/fd interoperability, custom `options.fs` operations, late option getters, cancellation, shutdown retirement, GC/OOM and complete original controls require review before claiming integration or parity.

## Windows child output handshake

Filesystem lane design checkpoint `629b9d4879bc91d01a6948a3458c3e383684f441` is a source-only design, not an implemented or reviewed runtime result. Its proposed secured OVERLAPPED inbound parent read endpoints have one retained 64 KiB pending/completed slot per channel. A read issued before pause may complete into that bounded slot; paused demand starts no new read and delivers no VM bytes. A ready read is copied into the transport Step span; the VM adapter copies it before push or another step.

Successful zero-byte ReadFile completion is not EOF. Only confirmed completed `ERROR_BROKEN_PIPE` proves producer EOF. Other errors, endpoint retirement acknowledgement and child exit remain distinct. Child exit cannot cancel stdout/stderr while descendants retain writer handles. Exact incremental cancellation and bounded quarantine contain native storage only, never Engine/JS roots; deliberate stream destruction does not grant child signaling authority. The current explicit Windows rejection remains a temporary source guard until this real ownership design is implemented and independently reviewed.
