# Google, Vertex and Mistral native facade candidate

The candidate implements actual provider request conversion and stream algorithms over QuickJS guest values in Zig. `native_ai_google_mistral_factory.create(engine, kind)` returns the ordinary `{ stream, streamSimple }` object accepted by `native_ai_compat.BuiltinApi`. No global provider is installed automatically.

Google and Vertex share Google-specific transcript conversion, thinking controls, thought signatures, model-family tool IDs, multimodal function responses, JSON-schema tool conversion and REST parameter mapping. The Vertex adapter resolves API-key markers, project/location options and provider environment overrides; its ADC branch directly calls the existing native authorized-user and service-account implementation. Mistral has its own transcript conversion, stable nine-character ID collision map, reasoning options, cache affinity, camel-case payload hook surface, wire remapping, usage aliases and fragmented tool decoder. None of these adapters forwards to an OpenAI provider.

The common factory retains model, options, payload, decoder, HTTP handle and callbacks in traced guest owner graphs. The transport uses the existing owned HTTP worker. Provider hooks are awaited through native continuations. Google and Vertex intentionally do not invoke `onResponse`, matching the actual upstream adapters. Mistral does invoke it, including for HTTP errors.
