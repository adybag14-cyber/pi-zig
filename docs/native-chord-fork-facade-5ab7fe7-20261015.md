# Private actual native Chord fork and guest continuation

The existing native fork owner and IPC transport already own exact OS processes, authenticated private loopback admission, byte queues and process-tree cleanup. They were missing the real VM-side facade and guest bootstrap. The new source authors a native forkDriver, EventEmitter-backed process channel, actual ipcLink, control/application taps, send completion tickets, exited Promise, inherited-lock removal and explicit own-lock override. Only the Engine's owning thread parses messages, dispatches callbacks or settles promises. Dedicated Engine pump/deinit hooks keep the runtime separate from other host control owners, and teardown joins every leased worker before freeing the owner signal or VM state.

The opt-in private guest executable authenticates the inherited envelope, removes its private port/token from the guest's copied process.env, exposes real process streams and IPC, and runs the actual entry through the existing native filesystem/package/CommonJS/TypeScript pipeline. Its complete package root is registered from the real factory after installing genuine context-only exports; it never first registers the compatibility context/JSON-only root. Node and output modules are actual native factories. The source also authors a native event loop with referenced timers and IPC listeners, natural beforeExit/exit, and an uncatchable native process.exit request. The ordinary application entry and default installation do not depend on this private target.

The shared Fork2 caller and real guest entry cover inherited lock removal, an explicitly owned real kernel lock, initialization, status/ready/shutdown control, application metadata, argument/environment projection, hidden transport credentials, stdout/stderr taps and mirroring, actual manager lifecycle, real process exit and owner retirement. The native diagnostic authors compiled inventory, observed cases and a fresh host-allocation baseline. The Source wrapper invokes genuine latest forkDriver, childControl, processLock and manager exports; its bounded oracle observer is passed through NODE_OPTIONS because original forkDriver intentionally clears execArgv. None of these Source/native programs has run yet.

This source is uncompiled and unexecuted. Nonempty Node execArgv currently fails explicitly with NativeChordExecArgvUnsupported; full Node flag compatibility is not implemented. Broader process.channel ref/unref behavior, general Node process compatibility, crash/send-error races, descendant-tree stress, complete host failure coverage, cross-profile/platform behavior and full application wiring still require qualification. Source observations are not captured, the composed host baseline is unknown, and no fallback success or fake fork backend is supplied. Full Node/Chord/Pi qualification and public activation remain false.
