Authority: Pi Source `b45e0ebcc5ae2fc42a6f2f23104d10e656e6bedb`, particularly `packages/ai/src/compat.ts`, `env-api-keys.ts`, and `utils/provider-env.ts`. Toolchain: stable Zig 0.16.0 and linked QuickJS-NG; implementation bodies are Zig/C. JavaScript in the fixtures is caller/reference input.

`native_ai_compat.zig` implements the global API registry and compatibility dispatch independently of configurable `Models`. Its `create` boundary captures actual builtin API streams, the builtin Models instance, and the env-key function. It preserves Map order, replacement and source ownership, wrapped API mismatch checks, builtin instance identity markers, reset and idempotent builtin registration, transcript normalization, explicit/scoped env-key handling, Cloudflare auth routing, and intrinsic async `complete`/`completeSimple` results. The capture boundary is private; it does not install public pi-ai package aliases.

The original Source observation fixture imports the unchanged real compatibility module through the official workspace export observer. All 36 recorded observations passed with the native implementation in Debug. They cover custom registered providers, registry state and wrapper identity, normalization, scoped OpenAI keys, Bedrock ambient markers, thrown identity, async rejection, and thenable result assimilation. Full reference checks covered 1,965 Source files, 31,064 installed dependency files, and 1,774 Node tool files with zero drift before and after capture. The ten builtin implementation bodies and real builtin network requests are outside those 36 observations.

The controlled native routing test separately checks the exact identity-sensitive builtin branch, Cloudflare Models fallback, empty auth-header handling, explicit and blank keys, overrides, and explicit builtin re-registration. Its provider functions are caller-owned test dependencies. This is an implementation test, not an original Source network comparison.

`native_ai_env_keys.zig` contains the original provider-env and env-key discovery algorithms, including all 39 provider mappings, Anthropic token precedence and bearer exclusion, Bedrock ambient auth, explicit and cached Vertex ADC checks, and Bun's cached `/proc/self/environ` fallback. Filesystem/home/path imports are captured dependencies, so an unavailable import retains the original readiness/browser branch. The native compatibility test uses this actual env-key implementation. A separate 72-case genuine Source capture covers every mapped provider, scoped/process/getter behavior, Bedrock ambient sources, real explicit ADC path checks, browser lookup, and the caller-controlled Bun fallback. Native comparison of all 72 cases and the complete native allocation-failure exercise passed in Debug.

`native_crypto_random.zig` supplies the narrow `getRandomValues` host needed by the native UUID implementation. It uses admitted native Io's secure random source, writes the real integer typed-array byte view, checks the 65,536-byte quota, and has no pseudo-random fallback. Native Debug tests exercise integer views, offsets, quotas, invalid kinds, retained roots, and actual UUID generation with secure bytes. A separate 33-case observation capture uses exactly `globalThis.crypto`, rather than the differently wrapped `node:crypto.getRandomValues` export. The first capture preserved a useful negative: Node observes a caller's own view getters. The corrected caller records that error rather than assuming immunity. The actual captured results and reference text built into the pinned Node binary established ordinary function constructibility, exact missing-argument diagnostics, three public byteLength reads, the BYTES_PER_ELEMENT read, and zero-size returns for detached/resizable views. Native comparison of all 33 cases, retained ownership, and the complete allocation-failure exercise passed in Debug. The fixture's original scope label says getter immunity; its actual authoritative row records the thrown getter error. `subtle`, `randomUUID`, and the remainder of Crypto are not implemented by this module.

The combined Debug gate passed 14 tests: six authored compatibility tests, two authored env-key tests, three authored secure-Crypto tests, and one imported unnamed storage test in each artifact. The compatibility inventory identifies every emitted name; the unnamed storage tests are not counted as additional AI feature coverage. All three allocation-failure exercises passed. The matching compile/runtime pair checked all 5,259 candidate source files and 19,546 tool files before and after execution with zero drift. The checkpoint proof validates the emitted inventory against the exact seven expected names. ReleaseSafe and production integration remain separate gates.
