The official [ExecuteAsyncModule algorithm](https://tc39.es/ecma262/2026/multipage/ecmascript-language-scripts-and-modules.html#sec-execute-async-module) attaches module completion handlers with intrinsic PerformPromiseThen. [ContinueDynamicImport](https://tc39.es/ecma262/2026/multipage/ecmascript-language-expressions.html#sec-continuedynamicimport) uses that same internal operation for loading and evaluation. [PerformPromiseThen](https://tc39.es/ecma262/2026/multipage/control-abstraction-objects.html#sec-performpromisethen) permits omission of the result capability, as the VM already does for await. These internal reactions do not use the public then method or its species-constructor behavior.

The proposed direct C change uses existing perform_promise_then with undefined resolving functions at those two internal module sites. It checks callback allocation and reaction attachment failures and propagates those failures through initial evaluation, dynamic-import rejection and ready ancestor execution. The public js_promise_then implementation is preserved byte for byte. No allocation-error classifier, fresh-generation predicate, user exception identity or timeout changes.
