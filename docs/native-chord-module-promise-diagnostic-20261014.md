# Internal module promise reactions

The d6dbf51f852783934f0e50cff899e5bbd3a1d0b8 native diagnostic preserved all Source50 behavior and both core allocation sweeps, but the new actual Source ResourceImpl4 replay and its successful allocation baseline both ended with JavaScriptPromiseUnsettled. The four unchanged Source cases succeeded in original Node captures. This negative remains retained; Source54 is not qualified.

The first resource case installs a throwing Promise species getter before its first await. The vendored VM begins executing a top-level-await module before attaching its completion reactions. Its internal js_execute_async_module then called public js_promise_then, which reads the species constructor. It ignored the resulting attachment exception and returned success, leaving the actual module evaluation promise pending. JS_LoadModuleInternal also attached internal evaluation reactions through public js_promise_then.

The official [ExecuteAsyncModule algorithm](https://tc39.es/ecma262/2026/multipage/ecmascript-language-scripts-and-modules.html#sec-execute-async-module) attaches module completion handlers with intrinsic PerformPromiseThen. [ContinueDynamicImport](https://tc39.es/ecma262/2026/multipage/ecmascript-language-expressions.html#sec-continuedynamicimport) uses that same internal operation for loading and evaluation. [PerformPromiseThen](https://tc39.es/ecma262/2026/multipage/control-abstraction-objects.html#sec-performpromisethen) permits omission of the result capability, as the VM already does for await. These internal reactions do not use the public then method or its species-constructor behavior.

The proposed direct C change uses existing perform_promise_then with undefined resolving functions at those two internal module sites. It checks callback allocation and reaction attachment failures and propagates those failures through initial evaluation, dynamic-import rejection and ready ancestor execution. The public js_promise_then implementation is preserved byte for byte. No allocation-error classifier, fresh-generation predicate, user exception identity or timeout changes.

The new private native_chord_module_promise_test target isolates pure guest fulfilled top-level await, native promises with poisoned own then, real thenable adoption, exact rejected-module identity, fulfilled and rejected dynamic imports, and a negative control requiring public then to continue consulting species. Its complete allocator-failure probe runs all those paths with actual VM GC and teardown. The actual ResourceImpl4 caller and golden remain unchanged; its failure diagnostics now print the captured exception and allocation index so the separate aborted-open continuation path can be investigated.

This is an unqualified diagnostic candidate. The aborted resource continuation still returns a nested promise from its callback; its generic promise-resolution path is being investigated independently. Native Source54, auxiliary complete allocation sweeps, fork integration, remaining exports and public Pi activation are not claimed.
