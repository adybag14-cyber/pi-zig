## Public native APIs

The existing `mcp.McpClient` and its CLI consumer remain unchanged. The new API is `mcp.session.Client`, operating through `mcp.transport.Transport`. `mcp.stdio_transport.Stdio` and `mcp.http_transport.Http` own their transport resources. `mcp.connection.Connection` provides a single opening attempt shared by callers, explicit retry delays and a native transient-error classifier, and a borrowed-client lease returned by `acquire()`. Release that lease before destroying or synchronously closing the connection on the same thread. Connection close cancels its initializing client, interrupts retry delay, joins opening, and waits for borrowed calls to release.

The client owns numeric request IDs, concurrent pending records, progress tokens, deadlines, notification writes, initialize metadata, and closed-state fences. Requests can be called from independent native threads. Positive finite request timeouts arm a deadline; non-positive or non-finite timeouts disable it, matching the source client. Progress notifications reset the deadline and invoke the supplied native callback. A callback failure is reported with its original Zig `anyerror` value. Initialize cannot generate a cancellation notification. Other timed-out or aborted requests send `notifications/cancelled`; pre-aborted calls do not send anything. Complete replies take precedence over a later close/abort. Close rejects unresolved pending work, cancels blocked transport writes/reads, joins their teardown, and then closes the transport. A remote RPC error retains code/message/data through `RequestOptions.on_remote_error`, with `McpRemoteError` as the native return error.

Native notification/progress/error callbacks receive borrowed values for their invocation. Synchronous request/connect/close from the same message-dispatch callback thread is rejected as reentrant to avoid waiting on its own reader. This is a native synchronous callback boundary; an asynchronous user callback bridge is subsequent work. The allocator must support concurrent allocation for concurrent calls and transport readers. Clients must be destroyed before their transports and callback contexts.

`capabilities` supplies paginated tools/resources/resource-template/prompts lists, tool calls, resource reads, and prompt gets. It stages complete pagination results, handles null/empty cursor termination, rejects repeated cursors and more than 1,000 pages, and fills missing resource/template names from their URI. Structured-only tool results get an empty content array. Server `ping` and configured `roots/list` requests are answered; unknown methods receive JSON-RPC method-not-found. `content.toLlmContent` projects text/images, embedded resources, resource links and audio placeholders, preserving full structured results separately.

`config.validate`, `namespace`, `matches`, and `toolExposure` implement server-name validation, exposure aliases, exact-name precedence followed by the first matching wildcard, stdio/HTTP field validation, and structural OAuth/provider-auth configuration checks. Validation uses the existing native URL parser and therefore retains its documented IDN bounds. `config.load` reads bounded actual global/project JSON files, collects errors, applies trusted project replacements or enabled/exposure/toolExposure-only overrides, preserves global credentials during an override, rejects namespace collisions, and excludes project provider-auth definitions. Untrusted project files are not read. Malformed JSON and file I/O errors use native typed diagnostic names; they do not reproduce V8 parser wording. File writing, command substitution (`!cmd`), environment interpolation, configuration UI, and user-extension registry integration are not part of this increment.

## Transport behavior

Stdio spawns a real native child, assigns only that child's POSIX process group or Windows job, and drains newline JSON-RPC plus a bounded stderr tail. Writes are serialized. Closing joins reader tasks, closes stdin, grants a bounded EOF grace period, sends POSIX TERM or terminates the exact Windows job, and escalates to KILL only while the original child handle/unreaped PID is retained. It performs the final wait before releasing ownership. The caller supplies the capability's environment map; omitted `Options.environ` is an empty environment, not an implicit global process lookup. Shell-script shims such as Windows `.cmd` launchers are not added here.

HTTP reuses `ai.http_fetch.fetchControlledObserved` and `ai.http_proxy.configureClient` for TLS/proxy selection, cancellation, and joined request teardown. Each POST carries MCP accept/content-type headers plus current session/protocol metadata. JSON responses and progressive SSE messages use the native protocol/parser. HTTP notifications discard acknowledged bodies. A GET SSE task starts after initialized notification unless disabled; its reconnect path retains event IDs/retry hints and uses bounded backoff/retries. Close cancels the GET task and in-flight POST operations, then sends one bounded best-effort DELETE when a session ID exists. No external account or authentication flow is exercised by the tests.

The SSE decoder reuses the native UTF-8 decoder, handles a split leading BOM/malformed UTF-8, joins data lines, processes comments/id/retry/event fields, resets per-event attributes, dispatches final unterminated data, and bounds both accumulated event data and partial lines. Callback failures preserve the native cause and seal the parser against further use.

A POST SSE response is closed once its matching response has been delivered. Notifications present in the same consumed chunk are processed; subsequent messages on that POST stream are not retained. Response-stream resumption via GET/Last-Event-ID after an unanswered POST drop is not implemented. GET resumption is supported, but the full upstream healthy-idle reset policy and every status/retry corner are not claimed. OAuth token/refresh/challenge handling is not wired to this transport; static caller-provided headers and typed auth-required/session-expired errors remain available. Sampling, elicitation, arbitrary server-request handlers, and full codemode/agent tool registration are subsequent integration work.
