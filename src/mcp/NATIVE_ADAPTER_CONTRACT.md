# Native legacy MCP client adapter

The legacy `McpClient.connect(argv)`, owned `McpTool` strings, paginated `listTools()`, and owned raw JSON-RPC `callTool()` response remain available. Live requests use native Session and Stdio/Streamable HTTP transports. Offline parser injection stays synchronous and independent. `connectHttp(url)` and `pi mcp --url <http(s)-url>` select HTTP explicitly; the existing `pi mcp <server-command> [args...]` syntax remains unchanged.

Omitted stdio environment inherits the calling process environment, including command discovery through PATH. An explicit environment map replaces that environment; an explicitly empty PATH is respected. No global environment mutation is needed. The compatibility facade retains its numeric request IDs, owned tool refresh atomicity, notification counters, remote-error enum, and timeout enum. An allocating Writer's allocation failure is reported as OutOfMemory.

`child` is a borrowed pointer to the native transport's actual retained Child, rather than a copy of process or pipe handles. It is valid until close/deinit. Existing callers that close stdin and wait on it are supported: adapter teardown joins readers and releases Control without waiting a second time after Child.id becomes null. Repeated close is safe; after close the facade may connect again. CLI error paths explicitly close resources before process exit (which bypasses Zig defers).

The compatibility facade is sequential. Its fields and close/connect methods are not a concurrent shared-client API. Pending-connect cancellation, concurrent requests, progress listeners, typed remote data, and GET stream ownership are exposed and validated by the native Session/Connection API. The bounded utility HTTP connection consumes request POST replies and their notifications; it does not open a separate GET subscription. It does not add configured-agent MCP tools, codemode, OAuth credentials, dynamic header commands, or Windows .cmd cross-spawn shim emulation.

The data-only adapter_stdio_28dc.json record was captured by the authentic upstream28dc McpClient and StdioTransport against the real native fixture, with PATH restricted in the owned Node oracle process. It proves initialize/version, two-page tool listing, actual call content, buffered notifications, repeated close, and owned child exit. Native tests additionally exercise actual pi.exe stdio/HTTP CLI output and usage, HTTP session/protocol headers and DELETE, remote-error propagation, bad-later-page atomicity, external child wait/reconnect, and an allocation sweep through initialize/list/call serialization. Windows/Linux Debug/ReleaseSafe terminal receipts are maintained outside the repository. macOS runtime is not claimed.
