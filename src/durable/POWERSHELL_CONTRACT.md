# Native PowerShell command tool

Authority: Pi `98d2e1947aa9c75dff4c20474d541873dadc1d05`, specifically commit `68c22123befa21bd43cb6110e023facbd466c333` and `packages/durable/src/tools/bash.ts`, `tools/index.ts`, and the PowerShell tests in `test/tools.test.ts`.

The existing public `tools.BashInput`, `BashExecution`, `BashPrepare`, and `BashOptions` names remain aliases to the shared native command module. `ToolSet.bash` retains its text-shell execution. `tools.PowerShellInput`, `PowerShellOptions`, and `ToolSet.powershell` add direct argv execution. The lower-level modules are exported as `durable.tool_bash` and `durable.tool_powershell`.

PowerShell defaults to `pwsh`, then `powershell`. Each program receives exactly `-NoProfile`, `-NonInteractive`, `-ExecutionPolicy`, `Bypass`, `-Command`, and one script argument. The script begins with `try { [Console]::OutputEncoding=[System.Text.Encoding]::UTF8 } catch {}` followed by a newline and the prepared command. The environment's text shell never parses this script. Command prefix is applied before the native prepare callback; the UTF-8 prologue is applied afterward. Preparation can change the command, working directory, environment overlay, and inheritance flag. Timeout validation precedes preparation.

Only `spawn_error` advances to the next program. A running program's nonzero exit, timeout, abort, callback error, or ordinary execution failure stops fallback. Empty program lists report `No command to run`. Output callbacks, retained-window options and skipped counts, spill thresholds (50 KiB / 2,000 lines), full-output diagnostics, original typed causes, and timeout/nonzero messages use the same native runner as Bash. PowerShell startup failures preserve the last attempt's native execution code/cause; missing-program messages are formatted as `spawn <program> ENOENT` for compatibility with the captured Node result.

On Windows, the executable search uses the capability's inherited parent PATH if the child environment omits PATH. An explicit child PATH, including an empty string, takes precedence. This matches captured actual Node/PowerShell behavior and keeps discovery separate from which variables the child inherits. POSIX lookup behavior is unchanged. This small Shell change does not modify process ownership, parent-job options, or command cleanup.

`durable_harness.builtins.createPowerShellTool(gpa, env, options)` returns a retained `PowerShellBinding`. Its public `tool` may be installed in a caller-selected extension, or `.install(registry)` installs the separate `pi.tools.powershell` extension. The existing default `Bindings` registration still contains read, write, edit, and bash. PowerShell retains tail output and has the upstream name, description, and command/timeout schema. The binding owns copies of programs, command prefix, working directory, environment overlay, and metadata; its environment capability and prepare context must outlive retained registry snapshots and invocations. Callers release their binding reference with `.drop()`.

`fixtures/powershell_98d2_windows.json` contains 15 authentic captures from the actual upstream `createPowerShellTool` and actual `NodeExecutionEnv`, under Node 24.14.0 with real installed PowerShell programs. The capture subclass records calls and delegates execution unchanged. Native tests compare exact argv/options, UTF-8/literal output, prefix/preparation behavior, absent and empty PATH, fallback attempts, all-missing and empty lists, nonzero/timeout errors, invalid timeouts, callback/prepare cause identity, and spill size. A native registry invocation separately executes real PowerShell.

The portable `pi-durable-command-fixture` records real argv, cwd, and child environment and supplies controlled process exits, output, and delays. It does not interpret PowerShell or emulate a shell. Its tests verify direct argument preservation, startup fallback, no fallback after execution starts, timeout/abort cleanup, skipped-output counts, spill size, and allocation failures on both operating systems. Passing these tests on Linux establishes native argv/ownership/output behavior; it does not establish Linux PowerShell language execution when an actual PowerShell interpreter is unavailable.

Native prepare callbacks receive an execution struct and `types.Context`; this increment does not add a QuickJS binding for user-authored prepare functions or expose the full upstream ToolExecutionApi to that callback. The existing native environment/Harness support limits remain in their foundation and scheduler contract documents. No Node, Python, TypeScript, or embedded JavaScript host implementation is installed by this increment.
