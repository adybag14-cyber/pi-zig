# Private Module package-input source successor

The selected incomplete edge was the native owner connection between the retained
PackageConfig cache and its intrinsic Error/Array results. The old draft created
and retired modules::BindingData, but never consumed its cache as GetPackageJSON.

The projected BindingData successor now consumes the null-ErrorContext path used
by CommonJS and TraverseParent. A native cache hit returns the stable Config,
read failures remain cached missing results, and an invalid Config stays uncached
and alive through intrinsic Error construction and inherited code setter reentry.
The binding target is retained in the caller Scope while native storage is used.
The serialization tail returns undefined on a missing result and a fresh intrinsic
six-element Array on success.

Four existing package cache/io/error/values donors are reused unchanged and pinned
in source-intake.json. The parser and ABI already in Main match the retained donor.
No donor file or Main file was modified.

## Focused controls

Six new declared controls use the actual Engine, shared Environment and typed
Realm binding slot, owned physical temporary files, the real libuv read path,
retained parser and native cache. They cover:

- Positive cache persistence after a physical change; fresh intrinsic arrays,
  protected from public Array/JSON.parse and inherited index setters.
- Negative physical read caching across file creation, with a new native owner
  seeing the file afterward.
- Invalid config remaining uncached while an inherited Error.code setter repairs
  the file and reenters the same binding; the original Error remains selected.
- Nonthrowing false native code Set preserving the intrinsic Error and permitting
  a later repaired-file read.
- Stable native Config addresses through real cache growth.
- Typed Realm cleanup, continued validity of serialized data, and release of the
  native memory owner.

The test bridge explicitly supplies a normalized native path. It tests this
private tail and does not replace callback permission checks or Module assembly.

## Review and integration

source-diff.patch shows the two production additions and additive install-only
build step. source-intake.json pins every changed/new source, the unchanged donors,
direct imports, shared Main prerequisites, and retained original authority.
Apply projected files and the four pinned donors only after Root review.

The future install-only target is build-native-node-module-package-inputs;
its filter is "native module package input", its root is
src/native_node_module_package_inputs_test.zig, and its Windows output is
native-node-module-package-inputs.exe. Six is an authored declaration count;
metadata and runtime have not been collected.

namespace ordering, native ESM Ada/FileURLToPath context, nearest traversal
assembler, stat/realpath assembler, full Module loader, or complete application.
