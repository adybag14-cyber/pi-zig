# Direct factory entry and real current producer

Independent Source review identified two finite frontiers in cbda7/6b0.
Both old checkpoints and prepared inputs remain immutable; no execution was
used to discover or conceal these source issues.

The direct readonly create entry now preserves actual pending/Bfb state before
any input validation, child fs/path install, or allocation. It balances native
diagnostic suppression and a stable invocation through actual owned Scope
retirement and final leave/checked return. The touched production Auth carrier
create and standalone createDefault have the same direct-entry boundary and
record their actual outcome before their construction scopes retire. This
does not rely on a calling SDK assembler having entered those guards already.
No namespace publication or shared Engine policy is added here.

The old current-event fixture marked an Error successfully as DATA before the
test, then merely threw that stored value. That did not establish a fresh
native OOM producer. The corrected callback really invokes
engine.throwNativeOutOfMemoryFatal during the tested signal call and owns the
observed newborn reason independently in a traced heap probe. It requires one
producer call, a new private generation, exact identity/fatal status, no later
work, and restored invocation/diagnostic state. The separate DATA profile still
tests successful marked DATA followed by ordinary returned-Promise rejection
and fulfilled return, with no flag clearing or name/message inference.

Two new genuine-owner negative entry controls supply the actual configured
bindings, seed an ordinary pending reason with a toString observer, then lower
the real VM memory limit to one byte while calling the direct factories. The
same pending reason must win before allocation; no module registration, reason
coercion or boundary imbalance may occur. The configured runtime memory limit
is restored immediately before host assertions. These are entry controls,
not fabricated successful SDK graphs or positive filesystem integration.

There are six typed genuine-owner control bodies, all uncompiled/unrun. The
sentinel remains fail-if-run and the build target has only an install edge.
Actual metadata, integration/runtime and whole-SDK qualification are unknown.
The explicit current G2/AF1116/Bfb and independently assigned namespace-owner
retirement/publication requirements remain unchanged.
