# Actual canonical Socket carrier publication for the TTY profile

The original retained TTY caller imports node:net to compare actual constructor
and prototype identities. A private Socket-only cache alone cannot satisfy that
public import. The explicit TTY profile now retains the SAME actual net carrier
and its default-export record before its last native adopter commit, then
publishes node:net plus a bare alias during the existing sticky public phase.
No Engine default bootstrap, Main or child selection is changed.

The carrier comes from the actual filesystem-owned canonical Provider/cache,
not a dummy Duplex, renamed class, fs.WriteStream or missing namespace fallback.
Its Socket and Stream fields are genuine constructor aliases. This selected
surface does not implement or claim TCP, Server, connect or createConnection.
Those remain outside this finite qualification scope.

Existing canonical/bare builtin records are preserved only when their actual
default is the supplied real carrier. The canonical export record is retained
exactly. Existing source modules conflict; no unrelated record is overwritten
or relabeled. Late host registration changes between private creation and public
installation fail explicitly. Existing legacy bare C modules retain their own
namespace object: this profile does not rewrite an immutable existing C module.
Fresh installs use one canonical node:net C module and the real alias API.
TTY/util/readline always use their separately required canonical alias identity.

All carrier/default/getter results use the assembly-local RAW normalization and
existing cleanup reducer. Default-export allocation happens before the final
adopter commit; public module failure remains sticky and retains the same native
provider, binding, code bundle and carriers. The allocation control now counts
all four canonical names and their four bare names without pretending aliases
are extra C modules.

Prepared controls remain UNRUN. Existing identity controls now check actual net
defaults and both host require forms. A new helper registers the real net record
first and verifies that canonical/legacy-bare records or a bare alias survive
installation unchanged. Its negative passes an actual events record and proves
it is rejected rather than used as a fake net namespace. These are source
controls, not actual captures or a native IO/GC qualification.

Filesystem owner confirmed public-child assembly currently creates another
Socket-only carrier even when supplied the same Provider. That unselected graph
must later reuse this published carrier/canonical cache and avoid duplicate
registration. No child compatibility or activation is inferred here. Actual FS
dependency source closure, alias/current-event review, concrete target and Root
runtime/ABI grants remain separate gates.
