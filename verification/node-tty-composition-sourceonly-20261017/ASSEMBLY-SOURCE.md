`9a34f1b200df4c62264198ee38a359c0fed9757e`. The imported reviewed products
are inventoried separately in `import-inventory.json`; historical manifests
and original Source caller files remain unchanged. No Main, Engine, C/header,

`native_node_tty_builtin_assembly.zig` composes the actual canonical Socket,
Hub, Scheduler, Wake and ClosePool types. It does not instantiate replacement
interfaces, duplicate a worker pool or install itself during default startup.
`native_node_tty_frontend_assembly.zig` is the actual embedded frontend entry:
it captures pristine runtime primordials and the frontend's original native
console mode, verifies live frontend ownership at installation, and passes the
actual global process and canonical Socket to the assembly. Remote hydration
and worker framed stdio are not native console capabilities.

The caller must install genuine classic streams, process/nextTick, node:module
createRequire, and native node:os first. The source uses the real createRequire
with an absolute physical filename. The same error bundle supplies `.tty`,
`.util` and `.codes`; util keeps the base range class, while validators receive
the actual Hide subclasses. Private internal inspect and public util are
distinct objects with identical actual inspect/format function values.
TTY's lazy readline lookup resolves the genuine four callback operations.

Initialization first reserves and inserts a native opaque holder in the
unregistered per-Engine values map. This is before guest getters or native
provider construction. Reentry sees `initializing` and fails without another
provider/adopter. The cache owns all exported carriers, code classes, native
owner, prepared binding, require and primordial roots. All temporary Scope,
message and color roots finish cleanup before `binding.commit`; that is the
last fallible native publication. Ready retries duplicate the same carrier and
constructor values and compare their actual import/native-authority identities.
Failed precommit initialization removes its private holder and retires only
its unpublished Hub resource. Failed native opens never become positive fds.

Public installation is explicitly separate. Actual default-export records are
created before the adopter commit, with `.default` pointing to the same actual
carrier. Six public names use Engine's real C-module API. Successful repeated
installation reuses the completed graph. A public registration failure retains
the completed private graph and exact new captured reason, if any, and becomes
sticky. Engine may already have reserved an immutable C module: this code
never claims it can roll that module back, retry its C registration, or consume
another adopter slot. A fresh Engine is required for that failed publication.
Preexisting unrelated public modules are rejected without replacing them.

Bare/prefixed imports share actual defaults, constructors and function values.
Engine currently creates distinct ESM namespace objects for distinct registered
names. The prepared original input records namespace equality separately;
this source does not claim alias namespace-object parity. Any normalizer/loader
change for that identity requires a separate Engine proposal.
