# Windows TTY factory and error registration continuation

This is authored source only. No compiler, AST, Node, native test, generator,
original capture or expected output was run or created. Public selection stays
off. The finite reviewed 356558e0 color/prototype packet remains historical;
its review does not cover this continuation or the Windows backend.

`native_node_tty_windows_factory.Factory(Socket, Hub, Scheduler, Wake,
ClosePool)` composes actual module types supplied by Root. Its inputs retain the
canonical Socket provider, the real net/process/require objects, initialized
error constructors and captured color primordials. It returns the actual TTY
carrier. Root must wrap that same carrier for default and named exports, once.
It registers no public namespace and starts no process.

`Binding.prepare` creates actual opaque classes and retained constructor roots
without publishing the adopter. The factory builds validators, colors and TTY
classes first, then `Prepared.commit` registers the actual known-brand adopter
as the final fallible operation. Socket's current `addHandleAdopter` validates
owner/duplicate/capacity before its infallible retained-root publication. No
allocation or guest operation follows a successful commit. Failed construction
releases temporary roots and removes/stops the newly registered Hub resource;
it cannot consume a permanent canonical adopter slot. Existing resource and
provider references remain held through their own teardown.

The new errors leaf uses construct-only native classes with actual Error,
TypeError and RangeError inheritance. Source class field `code` is defined
after super, without invoking inherited setters. Static fd formatting precedes
super; function message registrations call super first and then set message.
Prototype constructor getters report the captured Base. Node marker identity
comes from the proposed shared SystemError registry rather than a second
private symbol. ErrnoException uses the actual lazy `require('util')` result
and live `getSystemErrorName` method; it assigns errno/code/syscall in order.

The messages leaf follows the retained internal/errors source for the actual
TTY `expected='number'` profile, numeric separators, specific-type diagnostics,
string truncation and inherited constructor/name accesses. It takes genuine
private internal/util/inspect exports and captured primordial functions. It
does not replace the full inspector with the existing event formatter or a
placeholder. Other invalid-argument expected-type profiles are explicitly
outside this finite leaf.

Required before selection: independent source review of all new leaves and
the Windows native owner/pools; actual internal inspect/format and public util
composition; Root's canonical Socket/scheduler/close-pool intake and exact
shared-SystemError adapter review; real embedded frontend mode ownership;
legacy console translator capability and signal ordering; original controls
and native runtime qualification. The backend's Windows VT path and synchronous
write contract are concrete source, not executed functionality evidence.

Prepared causal controls in `original-error-registration.mjs` use the actual
public node:tty calls. They distinguish own class-field code from an inherited
setter, function.name's exact thrown identity, late global Function poisoning,
numeric/string diagnostic branches, and actual constructor/prototype/message
descriptors. None opens a valid fd. No expected values are invented.

Additional native controls for a later Root grant must use genuine dependencies:
force a late TTY-module getter failure after native owner creation; compare Hub
resources and adopter occupancy before/after; repeat failed assembly more than
four times; verify exact thrown identity and no diagnostic stringification;
then publish once and verify the SAME canonical Socket provider adopts a real
private-console TTY handle. Force commit capacity failure separately, and check
shutdown balances provider/mode/wake roots with no second close or VM callback.
These are control specifications, not runnable or accepted results.
