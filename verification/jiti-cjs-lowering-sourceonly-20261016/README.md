# First native jiti CommonJS lowering/evaluation unit

This source-only unit adds actual `native_jiti_cjs_lower.zig` and `native_jiti_cjs_eval.zig`. Tree-sitter parses user input, Zig validates/lowers it, and the linked C engine compiles/evaluates the generated user wrapper. No Babel, jiti, Node, TS compiler, downloaded dependency or production JS host implementation is executed. No public createJiti facade, default loader selection, module namespace stand-in or fake Module is registered. No compiler/formatter/AST/native/reference/generator job ran; all controls and both product leaves remain uncompiled/unrun.

Authority is actual jiti2.7.0, immutable gitHead `fd3bb289b75ed207edfb686d671ed50144f7e90f`. The peer's independently obtained npm archive/dist/source packet is retained by reference and its eval/utils/LICENSE/receipt copied byte-identically. New primary pipeline sources were downloaded as inert reference bytes from that immutable jiti commit. Its pnpm lock pins Babel helper-module-transforms7.28.6; that official tagged helper's metadata/live-reference/header sources and MIT license are retained too. `authority/pipeline-authority.json` records exact URIs/hashes. The recovery-pending old runtime is not used, revalidated or executed.

The actual plugin sets allowTopLevelThis:true, noInterop:!interopDefault and async from options; its loose default isfalse, lazyfalse, and the retained Babel helper inserts a strict directive unless strictMode isfalse. This unit accepts only that default module-transform profile, with explicit TS and async switches; assembly must reject unsupported custom Babel/plugins/loose/strict/source-map settings rather than silently ignore them. Because accepted modules have runtime exports, the nonenumerable, nonwritable, nonconfigurable __esModule header is required. Top-level this is retained as an expression, not rewritten to void0; the actual strict wrapper call supplies undefined.

Accepted first scope:

- Type-erasure-only TS or JS with at least one runtime export. NativeTS's existing parser/eraser remains unchanged. Runtime TS emission (enum, namespace, parameter properties, decorators, declare/abstract field emission), JSX and no-runtime-export modules reject explicitly.
- Named-only static imports and side-effect imports. Namespace/default imports, including `{default as x}`, reject until full Babel interop lowering exists. Escaped/non-ASCII module specifiers and non-ASCII/escaped identifiers reject. Imports group by source with the first surviving declaration's order. Explicit empty imports retain side effects; type-only specifiers, including comments, are elided. Unused TS bindings are removed after type erasure; unused JS imports still load.
- Live imported property reads, shorthand property keys and unbound imported calls. Rewriting reads through namespace properties avoids copying a binding's value. Conservative binding validation rejects any import/export name shadow needing fuller scope analysis, import rebinding and writes to exported bindings before execution.
- Readonly exported consts, named functions/classes, local export aliases, named/anonymous default function declarations and default non-anonymous expressions. Default arrows/anonymous class expressions, destructured exports, __proto__ exports and multiple exported anonymous initializer publications in one declaration reject explicitly. The compiler's generated identifier prefix and _default must not occur in original identifiers/labels, so this first profile has no guessed hygiene or default-name collision behavior.

The lowering uses actual Babel data-property publication, not a getter-export surrogate. Hoisted functions are available in the header before dependencies; nonhoisted exports initially hold undefined. Hoisted aliases form one header entry keyed by the first alias, matching the retained helper algorithm. Headers sort their entries and preserve its100-entry grouping and nested assignment order. Const initialization wraps the actual initializer, retaining reference/RHS evaluation order; anonymous const initializers publish after the declaration so inferred names survive. Classes publish after their declaration. Mutable exported binding forms reject until their writes can be lowered coherently.

Dynamic import and all meta properties (including new.target as well as import.meta), direct eval, reserved wrapper-binding collisions and unsupported runtime syntax reject before a prepared body is returned. Unhandled angle assertions and predicate/asserter annotations reject explicitly. The JS profile rejects TS-only optional parameters, modifiers, signatures, type import/export markers and readonly/optional/definite method/field tokens rather than retaining them into a later wrapper compile. Sync top-level await rejects; explicit async mode emits the actual async wrapper and awaited jitiImport dependencies. Computed method names retain the enclosing evaluation depth; only parameters/body enter method function scope. Comments, strings and untouched executable source are retained; code-string formatting, source-map/parse-marker diagnostics and full Babel generated text/stack parity are not claimed.

Source review successors normalize parentheses by their single non-comment expression, so named comment nodes cannot hide direct eval, unsupported default forms or an anonymous initializer whose name requires post-declaration publication. Original AST whole-statement type tokens also erase comment-separated explicit type imports before dependency collection, even when a value reference survives as an unbound identifier. Equal-offset edits close an initializer before post-statement publication, preserving semicolonless mixed declarations. Unhandled runtime-position abstract classes, class index/method signatures and optional method markers reject in the new leaf; fully erased type/interface/ambient/annotation subtrees retain hygiene/depth checks without treating their signatures as runtime syntax. These fixes remain in the new lowerer; the shared NativeTS implementation is unchanged. The original9419330b and514daa91 units remain preserved in Git history.

Evaluation is deliberately split into real operations:

1. `prepare(gpa, source, options)` performs all supported-profile validation/lowering before real Module/cache publication and owns its resulting body.
2. The Module/cache owner constructs the actual Node.Module, creates the actual nested jitiRequire/import/esmResolve context, sets require/path/paths, and publishes partial exports before compile, following genuine eval.ts. None of that is replaced by an ESM namespace proxy here.
3. `compile(engine, &prepared, filename)` creates the VM's actual seven-argument ordinary/async function without running the body.
4. `invoke(engine, compiled, actualModule, actualNestedJiti, actualPatheDirname)` reads Module.exports, Module.require, Module.filename, then dirname of a second Module.filename read, then nested.import and nested.esmResolve. It calls compiled with undefined receiver and exactly seven arguments and returns its owned raw completion, including the exact async Promise. It adds no adoption wrapper, loaded flag, cache deletion or interop mutation.
5. The existing owner applies actual compile/eval failure cleanup, onError/parse-marker handling and loadedExports/final interop at their proper boundary. Full jitiRequire/createJiti, resolution/aliases/options and asynchronous finalization remain separate missing closure; this unit does not claim they exist.

Compile/invoke recognize fresh captured native failures with the existing explicit-boundary exact-rethrow helper. Ordinary historical/lookalike reasons retain identity. No Engine, C/H, async primitive, CommonJS, existing NativeTS or Module-owner file changes are made. Native allocation, GC, cancellation, pending async completion and cyclic publication qualification still require separately granted composition controls.

`causal-inputs.json` contains19 actual user-module inputs (including owned dependency/cycle source),39 unsupported-input cases and an unexecuted native callback matrix. These are genuine caller inputs, not jiti/Babel/Module implementations or a generated expected fixture. They require the real source jiti instance and the actual composed native subjects. Source outputs/expected JSON are absent. The same inputs are intended to expose imported getter reads, undefined receiver, live aliases, strictness, seven argument identities/order, function-name inference, early cyclic exports, TS elision, source grouping, comments/await/JS-profile/runtime-signature boundaries, semicolonless edit order and raw reasons. No new Source48/39 capture or rewrite of old proof bytes occurred.

Operators owner `typebox_operators_resume` owns the real Node.Module graph/constructor/prototype/_nodeModulePaths/cache seam. Jiti evaluation uses actual pathe dirname, while Node.Module's constructor itself uses Node path.dirname; those are intentionally separate required bindings. The lowering/eval unit does not patch commonjs or compose over old plain-module cache records.
