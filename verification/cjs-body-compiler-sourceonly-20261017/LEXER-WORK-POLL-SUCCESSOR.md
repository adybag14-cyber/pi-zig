# Lexer work-poll successor to immutable 98954

SOURCE ONLY, uncompiled/unrun. The original 98954 regexp manifest and Git commit remain preserved. This successor closes two concrete already-documented parser work fronts without changing NULL legacy behavior:

- `lre_parse_escape_with_options` is a borrowed native opt-in entry to the actual same escape parser. The existing public escape API continues with NULL state. The private CJS/probe lexer selects the actual compile options at all four real escape-parser call sites. This bounds zero-filled `\u{...}` scans inside strings, templates, identifiers and private names using the same actual interrupt/pending mechanism; no grammar or diagnostics are guessed from text.
- The actual shebang helper has an optional context entry. Existing VM evaluation calls the old NULL wrapper; only the private CJS/probe entries pass their same context and observe failure before allocating the bookkeeping FD. It keeps actual UTF8/line-terminator semantics and does not fabricate a position.

Four new named controls (39 source declarations total; metadata unknown) exercise seven real CJS/probe inputs, each with 50000 zero characters inside actual escape grammar or a real shebang. The VM's existing 10000 interrupt cadence calls a native handler that returns zero with an actual owned pending object. The controls require the same exact reason, NONE category/unchanged probe flags, no replacement native Error capture, no job, GC and later real compiled-function execution returning 42. No interrupt counter, PC, parser result, clock or field is injected. These controls remain UNRUN.

The 98954 native Unicode/libc/retirement atomic boundaries remain explicit. Another concrete broader compiler frontier is not silently passed: resolve_labels has no internal cancellation and its existing failure path is marked unsafe. Its peephole/dead-code work releases atom references while the original FD input bytecode still contains their operands; a naive new goto-fail poll could make FD teardown revisit released atoms. Root has been told. The mandatory label/relocation algorithm and opt-in atom-ownership-safe cancellation policy require a separate narrow successor and review before final combined compiler qualification. No error string is an operational classifier, and the new escape adapter does not alter that policy.
