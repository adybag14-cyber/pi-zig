# Opt-in regexp compiler implementation

This is the actual SOURCE implementation over 531eed654092dd3940155fd5ecf84a068b617fc5, following REGEXP-OPTIN-COMPILE-PROPOSAL.md under Root's explicit source-authoring grant. Nothing here has been compiled, parsed by a tool, formatted, queried for metadata or executed. No Main, Engine, default selector or historical proof was edited. Independent exact C review is required before composition or execution.

`lre_compile_with_options` accepts a borrowed native `LRECompileOptions` record. The existing `lre_compile` signature/symbol delegates with NULL. NULL options make no new poll/capacity callbacks, retain the original rqsort and retain original allocator opaque values. No option, callback, native parse-state pointer or format flag enters returned bytecode, strings, regex objects, jobs or serialization. The execution timeout/bytecode format/regexp matching engine is unchanged.

Only `js_compile_regexp` inside the already-opt-in CJS/probe diagnostic scope selects these options. The actual poll calls `js_pi_compiler_poll` on the same JSContext, including actual-current checks and the existing counter/trusted interrupt callback. A nonzero result latches the native compilation as aborted. No later poll callback runs. Nonzero-size native allocation requests then refuse to continue; size-zero cleanup remains available. Native list/range/buffer retirement does not poll or produce a replacement JS diagnostic. The existing QuickJS boundary owns any actually pending reason before freeing the pattern CString or compiled bytecode and restores that same reason. There is no message/name/prototype/flagged-data operational classifier.

The capacity callback is a scalar producer: it sets the private diagnostic capacity_failed field, without allocation, JS or fatal inference. Capture count, named alternative scopes, register stack analysis, encoded ranges and signed bytecode ceiling report their existing real limits. The finite audit additionally found the fixed 128-byte group-name buffer; reaching its actual guard now reports GROUP_NAME. Opt-in string-table/gather/sort allocation arithmetic is checked and reports STRING_STORAGE at the actual overflow/representation guard. A capacity failure without a pending reason still follows the existing actual SyntaxError construction, but its trusted completed syntax category remains NONE. Existing allocator/stack/interruption provenance stays separate. No allocation event is fabricated from a size-zero free or optional recovered VM shrink/hash attempt.

Polling covers recursive parser entry; alternative/term/disjunction work; decimal and unbounded Unicode escape scanning; capture/class/name lookahead; named-group lookup; Unicode property-name and string-set parsing; string hash/collision/initialization/rehash/copy; union/intersection/subtraction/canonicalization; string gather/sort/emission; range emission; quantifier-bytecode analysis; and final register analysis. Boolean lookahead helpers retain their existing return shape while the sticky abort is checked before subsequent recursive entry, at the term boundary and before compile completion. The quantifier analysis caller checks the sticky failure before using its output. New inter/sub lookup code propagates -1 rather than converting a failed search to a false membership result.

The opt-in string-set sort is a checked, charged native scratch vector and bottom-up stable merge sort using the actual existing length-only comparator. It polls each merge/copy step; the legacy sort remains unchanged for NULL options. Scratch holds only borrowed REString pointers. Cancellation may leave pointer ordering partially changed but never node ownership. Hash rehash unlinks each moved old node before inserting it in the new table; on interruption native cleanup frees only the moved nodes, leaving unmoved nodes to the original list owner. No node is freed twice. Unicode sequence callbacks now retain their actual add-failure in the opt-in list rather than losing it in the void callback.

The finite native atomic frontier is explicit: libunicode CharRange union/intersection/inversion/compression/case canonicalization and static property/table expansion remain existing native operations, bounded by the Unicode universe/table sizes and represented range count. Their allocators use the sticky native adapter, but internal libunicode scans/sorts are not new poll sites. libc realloc/memcpy/memmove and DynBuf native copies likewise remain atomic operations bounded by the existing bytecode/native storage ceilings. Native cleanup loops deliberately have no failing polls. This does not claim instruction-level cancellation inside those operations, exhaustive allocation coverage or closure of every broader CJS compiler resource frontier. In particular this delta is not the final combined compiler/probe source qualification.

Nine additional named controls are prepared (35 total source declarations; actual compiled/imported metadata unknown):

- Actual CJS and detached-probe capture overflow gives operational NONE; a genuinely malformed regexp still completes ordinary syntax; actual Unicode string-set compilation executes only after the returned function is called, followed by GC/reuse/no jobs.
- Raw actual LRE compilation compares opt-in bytecode with legacy/explicit NULL for the same ordinary pattern, and verifies NULL makes no callback.
- Real capture, nested-quantifier register, named-alternative scope and fixed group-name limits each report only their actual capacity producer.
- A 32-string Unicode-set baseline measures actual opt-in poll work, then cancels at every measured position (bounded to 100..16384). Every attempt requires NULL bytecode/length zero, one exact pending object, no repeated callback, no capacity report, native cleanup, GC and successful reuse. It reaches actual hash construction/resizing and opt-in merge sort; no clock or parser result is injected.
- An already-pending raw reason is preserved at the first opt-in poll before header allocation.
- A sixth measured actual allocator sweep compiles a real Unicode-set CJS body, covering native string-table and scratch allocation events. It retains the existing actual-event measurement, recovery/first-reason rules, owned-value/native-block teardown and finite 512-event admission. This is not every logical small allocation.

The encoded-range, bytecode-ceiling and string-storage arithmetic guards are statically reviewed producers but do not have giant-memory capacity executions prepared. None of the controls has run. No Source expected output or whole Node24/V8/jiti/bootstrap parity is asserted. Context retention, correct-context capture-only native stack owner, balanced diagnostic suppression and trusted nonreentrant interrupt host attestation remain mandatory, as before this delta.
