This unit adds the real public lib/jiti.mjs wrapper, its module-scoped
lazyTransform/onError/nativeImport declarations, and concrete composition of
the reviewed real native internal bodies. It is an unselected native consumed
profile. No Node/reference/generator/fmt/AST/compiler/native job has run, no
expected observations exist, and no complete bootstrap or default application

## Product/API

- native_jiti_native_import.create(engine, physical_basename) creates the
  actual nonconstructible, non-AsyncFunction arrow named nativeImport, length1.
  A VM-traced C-function-data root captures the physical lib/jiti.mjs basename.
  Its raw C callback forwards the borrowed specifier to qualified C3
  JS_PiDynamicImportGraph0 and returns the exact intrinsic Promise/exception.
  It does not use Engine.checked on invocation, inspect then, adopt a Promise,
  create an AF, use JS_LoadModule, or consult an ambient private graph.
  The forwarding contract is the already qualified Root141989E9 binding;
  captured-argument/metadata adaptation is new and itself remains unrun.
- native_jiti_public_factory.create uses only core_graph.createCanonical to
  construct the real cyclic core/frontend/require declarations. Its createJiti
  is an ordinary constructible declaration, namecreateJiti/length1. An undefined
  options argument gets a new object; null is not normalized. It reads
  opts.transform before the conditional object spread. The fallback overwrites
  the transform data property after the spread, then creates parent fields in
  onError/nativeImport/createRequire order and calls the actual core with
  undefined receiver and exactly three arguments. A truthy custom transform
  is retained without copying the original options at this boundary.
- lazyTransform is ordinary/constructible, length0. Its private null-prototype
  lexical cell caches only the successful raw result of
  createRequire(import.meta.url)('../dist/babel.cjs'). Failed loads and falsy
  cached results are retried as Source specifies. Calls have undefined
  receivers. The cached transformer result/Promise is returned raw.
- native_jiti_profile.prepare consumes COMPLETED actual namespace capabilities,
  creates real resolveOptions/escape declarations, the actual module-scoped
  resolve RegExps, real cache/transform declarations, the reviewed native
  default transformer, and canonical public/core/frontend/require graph. It
  shares exact debug, resolver, path, transform, cache and regex identities.
  Actual mlly/pathe/utils namespaces retain their own module lifetimes; they
  are not reconstructed per createJiti invocation. Native default output is
  routed through the existing canonical evaluateLowered path, never API12a
  lowered twice. Actual std-env isWindows is an explicit immutable import;
  core initialization separately calls real node:os.platform as Source does.
- prepare returns only a host-private move-only preparation. A real Node owner
  must publish its new native Babel Module (cache-before-initialization,
  parent/children/path/paths/loading/loaded/failure semantics remain its job).
  complete checks the actual Module._cache identity against engine.commonjs_cache,
  its physical filename entry, exact module object/exports/filename and loaded
  true. It never creates a surrogate cache, fake Module or require callback.
  These identity checks are publication preconditions, NOT a brand/provenance
  proof for arbitrary guest objects; the API accepts trusted host capabilities.
  Only then does Engine.valueNamespace create a real ESM exotic namespace with
  default and createJiti pointing to the SAME genuine declaration. Repeating
  complete returns that same namespace. Failed completion remains failed;
  no partial namespace is cached by this unit.

All owned native callable roots use existing traced/aggregate-charged callable
storage or actual C function-data roots. Host Prepared is move-only and must be
deinitialized once, in its original Engine, after its publication/rollback.
Completed callable roots retain the actual graph; dropping temporary handles
does not break old closures. Engine.valueNamespace uses context-owned C modules
under its existing lifecycle; this unit does not add graph GC/reclamation or
claim bounded retirement of arbitrarily many installed modules. No Graph2
vendor prototype or importer frontend is included.
