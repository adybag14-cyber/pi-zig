## Build and custody boundary

The dedicated step is
build-current-main-jiti-sdk-agent-compile-only-artifact. It depends only on
b.addInstallArtifact of its b.addTest compilation. It adds no Run step, query,
reference capture or relationship to existing runtime targets. It does not
register a default module or add this artifact to ordinary application selection.

The root uses the current Main linkQuickJs, linkTypeScriptParser and linkSqlite
helpers and actual catalog_tool module. Those helpers bring the current QuickJS
and engine C3 ABI, native ICU/C++/YAML, Photon, durable process C helper, SQLite
and real TreeSitter/TypeScript parser library. In particular, TreeSitter is linked
explicitly; merely retaining lowering declarations would miss its actual linker
dependency. No old C2 files or copied library configuration are used.

The selected CURRENT_MAIN_COMPILE_LINK_ONLY_SENTINEL_NEVER_EXECUTE test returns
error.CompileOnlyArtifactMustNotRun if somebody executes it. That sentinel MUST
NEVER RUN. The artifact has no approved runtime or metadata-query use, and the
build step supplies no runner. Other selected real test bodies are compiled but
also must not execute. A link-only success cannot establish their results.

Root alone will grant and supervise a later compile/link attempt after the
exclusive native runtime lane is released, under the current full sealed-source/
compiler/dependency/ownership protocol, fresh16GiB admission, Debug LLVM and-j1.
This preparation issues no grant and does not run compiler, AST, formatter,
generator, Node, native artifact, query, reference or sentinel. Independent Body
source review and actual compile/link remain separate pending requirements.
