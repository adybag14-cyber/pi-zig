Two concrete limits block a wrapper-only positive parity claim. First, the inspected unwrap continuation installs resolve_reject[1]=JS_UNDEFINED. It has no handler closing a sync iterator on a rejected yielded value, nor a close around a synchronous PromiseResolve failure. The current ECMAScript algorithm includes conditional rejection closing; genuine pinned Node observations are still unrun. Second, the active API closes some step failures as if they occurred in the body, and lets a return getter replace an existing throw. Acquisition alone does not fix either category. The standard separates step failures from body close and preserves an existing throw over close failures. [AsyncFromSync continuation](https://tc39.es/ecma262/2025/multipage/control-abstraction-objects.html#sec-asyncfromsynciteratorcontinuation), [for-await body evaluation](https://tc39.es/ecma262/2025/multipage/ecmascript-language-statements-and-declarations.html#sec-runtime-semantics-forin-div-ofbodyevaluation-lhs-stmt-iterator-lhskind-labelset), [AsyncIteratorClose](https://tc39.es/ecma262/2025/multipage/abstract-operations.html#sec-asynciteratorclose).
