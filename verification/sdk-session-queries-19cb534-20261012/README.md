# Native AgentSession callable and fork queries

The public getCallableToolNames and getUserMessagesForForking methods now have native Zig bodies through the linked C VM. Callable discovery uses the actual retained tool registry and upstream direct/codemode/deferred exposure rules; it preserves live private-method, getActiveToolNames, structural Set.has, Array.filter and returned-value map lookups. The helper retains registry values before guest callbacks, and wrapping no longer dereferences a potentially replaced registry record after reading guest definition getters. Tool wrappers keep their cached identity.

Fork queries use the actual manager's current getEntries result, support original iterators and iterator-close error precedence, select user message entries, and concatenate text parts with the original empty separator. Strings, whitespace, raw getter/callback errors and entry identifiers retain Source behavior. The existing default-newline text helper remains available to other consumers.

Genuine unmodified upstream 19cb534 observations cover four actual SDK factory configurations and their three loadout states, seventeen live-hook cases, and thirteen fork-query cases including a real original in-memory SessionManager. Caller overrides exercise Source behavior; Source class/prototype implementation bodies were not replaced. A temporary forwarding Array.filter override is explicitly part of the hook input. Reference runtime/tool pre/post verification covered 31,064/1,774 files with zero drift.

Initial native replay compiled with eight controls passing and failed with TypeError because the public query method was absent. The first repaired gate passed 10/10. Expanded qualification passed 11/11 and 156/156 build steps on Windows Debug/default backend/pinned Zig 0.16.0. Every one of the 39 observed host allocation indices in the query phase was induced; each returned OutOfMemory, recorded an actual allocator failure and balanced all allocated/freed bytes after full owner teardown. Factory setup runs before the injected phase and is not claimed as a newly exhaustive factory allocation gate. Source/tool integrity and process retirement are recorded in the accompanying actual posthash receipt.

Full SDK/session prototype/state parity, the other public methods and getters, Chord Host lifecycle, public native-default activation and removal of the legacy host remain unfinished work. This component checkpoint does not establish those requirements or a cross-platform pass.
