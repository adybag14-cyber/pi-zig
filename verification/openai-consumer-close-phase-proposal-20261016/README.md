The [ECMAScript 2025 ForIn/OfBodyEvaluation algorithm](https://tc39.es/ecma262/2025/multipage/ecmascript-language-statements-and-declarations.html#sec-runtime-semantics-forin-div-ofbodyevaluation-lhs-stmt-iterator-lhskind-labelset) places next call/Await, result-object validation, done and value access before the body completion/close path. The [2025 AsyncIteratorClose algorithm](https://tc39.es/ecma262/2025/multipage/abstract-operations.html#sec-asynciteratorclose) takes a completion of GetMethod(return), then call and Await when appropriate, and returns the original throw before propagating an ordinary close failure or validating a close result. These are normative derivations, not captured Node observations.

The proposed changes are deliberately bounded:

- Clear `iteratorActive` before calling the retained next method. Keep it false throughout its Await and result getters. Acquisition is also outside the body region.
- Enter the body region only after successful `value` access. The existing hook Await and decoder.push then close once on ordinary body failure. Returning to next exits that region first.
- Preserve the saved original body reason when the return getter or call throws. The private discard helper frees only the discarded ordinary captured close reason. It calls the existing `async_body.rethrowRecognizedAllocation` with the explicit get/call boundary generation, using the existing private tag/span rule to mark and rethrow the exact fresh captured reason as JavaScriptException. Direct host OOM and already uncatchable exceptions also escape. No active Engine or AF helper changes are needed. Converting that tagged captured reason to OutOfMemory would allocate a new reason in the AF primitive, so this proposal deliberately preserves its original identity instead.
- Keep the existing close Await action and `.closed` handling. An ordinary rejected Await or primitive fulfilled close result preserves the original body throw. Nullish return avoids the Await. No extra Await, Promise wrapper, next property lookup, or getter observation is introduced.
- Select the private stage before rejected-reason classification. Save `closeGeneration` at the return-call boundary and use it only for `.closed` rejection recognition; retain the existing IIFE generation for every other Await. This prevents a caught tag born earlier in the IIFE from becoming a falsely fresh close rejection. The additional private BigUint/state allocation may fail fatally and needs native allocation qualification; it adds no guest getter or Promise job.
