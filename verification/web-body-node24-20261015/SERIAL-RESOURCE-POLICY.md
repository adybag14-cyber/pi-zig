This isolated Body lane may admit exactly one native owner with freshly measured available RAM of at least12GiB and zero other native processes. Other heavy lanes retain their16GiB floor. Original16GiB runners, previously rejected admission artifacts and all semantic/reference gates remain unchanged.

`run-native-serial-resource.ps1` retains the original complete candidate/vendor/compiler/source/dependency/Node/control/authority inventories and84absences before, between and after phases. The owner records native root PID, parent PID, executable digest/path, full command line and UTC creation time. Approximately once per second, it discovers descendants only through currently verified retained parent identities, records each exact child identity and immutable ancestry chain, tracks Windows per-process lifetime peak working set, sampled aggregate owned RSS and available physical RAM. Resource samples and identity/terminal receipts are durable; JSON state writes use replacement from a private temporary file.

If available RAM falls below4GiB or the original owner deadline expires, the owner records the cancellation reason and revalidates PID/UTC creation/executable/full command line/parent PID plus retained ancestry immediately before each termination. Each child has a retained Diagnostics.Process handle, forced open and checked against the CIM creation time at its microsecond precision when captured. Cancellation calls that retained handle's Kill(false), eliminating a termination-by-reused-PID race. It stops only verified owned identities, leaf first, with bounded recapture and settlement. A reused PID is unrelated and is never stopped. Codex or host executable paths are excluded from ownership/control. Exact owned-identity absence is checked independently after terminal state; a still-live identity or unverifiable absence prevents success. Resource supervision failure attempts cleanup of already retained, verified identities even if new descendant capture fails. Handles stay open through the absence/summary checks and are disposed in finally.

Standard-output/error tasks must complete within the remaining10s settlement budget using bounded Task.WaitAll. GetResult is called only after both tasks are completed. A pipe that does not settle produces an explicit pipe_settle_failure receipt; it cannot block the owner indefinitely or produce a pass.
