# Node SQLite corrective source packet v3

This packet supersedes the product and prepared-control scope of `prepared-v2.json`.
The original packets remain historical. No compiler, parser, AST, Node, native,
generator or reference-capture job has run for this unit. No expected or observed
outputs are supplied. Actual test enumeration remains unknown until a separately
authorized matching build/query. The default build and namespace are unchanged.

The four leaf products preserve the actual c268 Node adapter algorithm. Await
rejected values are DATA even when an actual Error carries a private allocation
tag or an uncatchable bit. Transaction rollback and failed-open close therefore
run and retain the exact original rejected value. Actual pending VM events are
normalized before rooting a returned value, native allocation, SQL binding,
stepping, subsequent getters or enqueue. Local callback capture isolation rejects
a missing new reason rather than reusing an older diagnostic.

Root's explicit provenance decision applies: a preexisting captured flagged
diagnostic is history without explicit current producer ownership. It cannot
prevent the callback body by flag alone. An actual pending event comes first;
a fatal newly captured by the current operation is retained even if that
operation returns success. During local cleanup the selected owned reason stays
outside the VM and Engine slots. A first actual cleanup fatal promotes over an
ordinary reason, and a first fatal survives later ordinary or fatal cleanup.
There is no flag clearing, shared Engine policy edit or classification of Await
DATA from flags/generation. The callback's direct host-OOM contract follows the
existing native callback boundary; arbitrary foreign native callbacks that both
return a direct allocator error and install an unrelated primitive exception
are outside this finite producer contract.

`StatementSync.all` now resets after successful parameter binding on every exit,
including SQL/row/range/allocation failure. Bind failure ordering is retained.
Database construction selects the live superclass before evaluating `new Map()`.
The internal Queue's primitive `newTarget.prototype` uses intrinsic Object.prototype.
Zero-length ArrayBuffer views retain legal empty binding behavior without making
up a nonempty backing pointer.

The original 25-row observer, its input/source copies, and all four original
native test declarations are unchanged. The additive correction observer has
four genuine original-caller rows: rejected transaction cleanup, rejected
configuration cleanup, superclass selection before Map effects, and Queue
primitive-prototype fallback. Its Node input imports byte-exact original c268
source and real node:sqlite. Its native input uses the same caller and actual
private/flagged Error DATA. Complete comparison is available; no snapshots have
been cloned or authored.

The additive Zig file declares nine controls:

1. Actual pending before first GPA root append, with a returned object's native
   finalizer raising a second exception and a real armed failing allocator.
2. Real named getter and Proxy ownKeys successful returns with pending events;
   no subsequent getter/root allocation/SQL insert is allowed.
3. Actual new-target prototype getter pending before database allocation, plus
   a direct factory's cached-module pending guard.
4. Queue relational coercion pending before enqueue and a real SQL insert.
5. Genuine shared-memory two-connection visibility and a deliberate held-reader
   SQLITE_LOCKED precondition, followed by All range failure and a second writer.
6. Actual flagged untagged, fresh private and historical private rejected DATA
   performing rollback/close and the same constructor/prototype caller cases.
7. Historical flagged capture permits body, actual pending wins without body,
   and a newly produced captured native fatal survives a successful return.
8. Real finalizer cleanup promotes ordinary to first fatal and retains first
   fatal over later ordinary/fatal, with balanced diagnostic suppression.
9. A callback reporting a new exception without a new reason cannot rethrow an
   older diagnostic as that new failure.

Shared-cache support is a real prerequisite for control5: unavailable support or
a missing lock precondition is an explicit failure, never a skip or fallback.
It proves shared-table-lock cleanup, not physical WAL/pager behavior. The separate
`allResetWithOwnedFile` helper is prepared for a future Windows path/lease grant:
it refuses an existing file, restricts the contained path, checks physical
ancestors, establishes a genuine SQLITE_BUSY reader-lock precondition and leaves
the resulting file intact. It is not called by the nine declarations and has
not received a path grant or run.

The original strict `checkAllAllocationFailures` control remains intact and
unrun. Host OOM during bare-name cache construction is a fatal boundary: discard
that Engine/connection; ordinary retry/recovery of a partially built cache is
not qualified. SQLite's own allocator is separate from the Engine GPA. None of
these controls establishes complete node:sqlite API support, runtime parity,
namespace installation or restored upstream-runtime authority.
