# Genuine POSIX original renderer captures

This private capture workflow checks out original Source `1692bba6347a287ab0f3cb554a4430fafffc474b` on actual Linux and macOS runners. It installs the exact original lockfile with lifecycle scripts disabled, then invokes the unchanged official catalog hydrator against pinned typed metadata SHA256 `439c53478c84ed27a58f8b54e1c3bd45810e5a969515b4e3666a3898d51ee22f`. That metadata is an oracle dependency; qualification of the latest generated model catalog remains separate.

Every original tracked file must remain byte-identical through dependency installation and hydration. The resulting original Source inventory must contain 1912 tracked files and 43 hydrated metadata files. Each capture freezes that full Source, all installed dependency files including nested workspace dependencies, the complete pinned Node 24.14.0 installation, and the complete candidate tree. Every observed original module must belong to one of these frozen inventories and match its hash.

The original find/ls/grep renderers run all 59 unchanged caller cases twice. The original Bash/PowerShell renderers and duration helper run all 53 unchanged caller cases twice. Both families use their actual original Theme, Text/Container/Spacer, VisualLinePreview, timer scheduling and helper implementations. Source bodies, thrown values and captured rows are not rewritten or normalized.

The workflow retains independent raw Linux/macOS captures and compares each family's two captures exactly. It also records whether each platform's original rows equal the historical Windows rows. A platform difference is retained as evidence for a platform-specific native fixture; it is never erased or accepted by a TypeError catch.

Each Node capture has a 256 MiB heap bound, a fresh 2 GiB available-memory admission check, its own exact process identity and a 300-second owner deadline. The original metadata hydrator has a 128 MiB heap bound and its own owner receipt. Source/dependency/Node/candidate manifests are verified before and after every capture.

This workflow creates original Source evidence. It does not qualify native renderer allocation ownership, activate the public SDK factory, or certify the full application.
