# Genuine native SDK owner, prepared source

Baseline: Root `7edd833dc8d61311814f153fddbb1205abb008c1`. No Main, C/H,
Engine or shared Scope is changed. No compiler, parser, formatter, Node,
generator, native test or metadata job has run. No default backend is selected.

`native_sdk_application_owner.create(engine, Inputs)` is a concrete host owner.
It captures the actual bound stdio Frontend through the real FS Inputs owner,
constructs the actual Auth runtime over that same process/lease, then creates
the actual private package suppliers, PackageManager assembly, exec/MCP and
extension loader, Chalk and existing SDK application factory. The call supplies
`.native_zig` and the real physical config module URL. It does not accept a
Completed record, invent a constructor, publish a partial coding-agent module,
evaluate an implementation in JavaScript or return a fake session.

The move-only result retains Inputs, the actual Auth/frontend/runtime owner and
the application graph. `factoryExports` returns the actual existing factory
subset, not the whole public coding-agent namespace. `authStorage` returns the
real authenticated module. `takeOverStdout` and `restoreStdout` execute the same
real output-guard functions at the actual mode transition. The query is not
derived from TTY state or a mode flag. `retireInto` consumes roots into an
already recorded SDK completion; it does not unbind a frontend, close a Hub or
control a process. Bridge, environment and provider contexts outlive Engine.

## Concrete producer corrections

The old paths producer constructed fresh functions on every call. Configuration
and PackageManager therefore captured different copies of one Source module.
The revised producer retains one private namespace for the exact filesystem,
and completes its actual process/spawnProcessSync imports once. Repeated calls
retain namespace/function identity and subsequent ordinary export mutations.
Different imports reject. Synchronous same-phase reentry rejects. Constructor
temporary and diagnostic retirement finishes before basic cache publication.
Cloud import roots are privately reserved before defining the real export,
with owned rollback on failure; a failed definition never reports a completed
cloud import profile. This is not a claim of general VM allocation atomicity.

The reachable filesystem platform/Auth factories also had bare Scope retirement
and cache publication before cleanup. Their actual bodies now record completion
before each native root retires, and publish only after construction retirement.
Actual getters/callees are checked at their own operation generation, then the
closed `ownRoot` stores the owned result. Typed storage OOM is recorded before
the incoming sole carrier is freed. Each consuming definition normalizes its
actual result before the next operation. Cached Auth dependency getters still
run; their Source order and identity checks are preserved. Source guest
catch/finally/IteratorClose is never replaced by these native-free helpers.

The helper is exactly Root's C435 successor from closed `62ded415`, with Async
receipt CD583672. Its 11357-byte 41AA prefix is unchanged. This unit does not
repeat or expand that helper review.

## Actual dependency joins and unqualified frontiers

The new assembler deliberately imports the real supplier APIs, even where their
separate Source intake is pending. It is not yet a standalone buildable public
SDK. The manifest records exact donor files and status. The required joins are:

* FS Inputs c279/cf77/27a and actual a4db frontend/output-guard transport;
  same real internal builtin require f360 must reach util/TTY/Errno and pass
  `validateInstalled` after genuine util publication. These are not public
  createRequire substitutes. Native descriptor and provider owners stay live.
* Auth-only owner f599 (full peer still pending), real six Auth AF/reload owners
  already in Root, and the separately authored true File2 AF owner. The
  assembler rejects prototype-only file methods. Readonly Auth's actual binding
  additions are owned separately; no Readonly Source is copied here.
* Private semver six and Chalk cd145 are in Root; Git5f9 and exec5b744 are finite
  Source closed but require separate Root intake; ignore ac784 is Source peer
  pending. These are real private producers, without global module aliases.
* Actual canonical Module/createRequire/_load and native Jiti/queued import
  providers remain mandatory. The private Module owner check rejects the old
  CommonJS facade. Public CJS/ESM/TS loader completion is still owned by Auth
  and Operators. No placeholder resolver or identity transformer is accepted.
* Virtual module names must eventually resolve to completed actual namespaces,
  including the whole coding-agent public namespace; the factory subset from
  this owner cannot silently satisfy that public export contract.

This finite source unit covers the new aggregate owner and paths/filesystem
factory boundaries. It does not qualify all inherited scopes inside package,
extension API/lazy modules, text/path algorithms, configuration, shell or
manager factories. Their reachable cleanup/cache frontiers remain explicit
follow-up work. Existing C module registration failure is sticky after VM
publication; no shared Engine policy is rewritten here. Root's separate G2,
current C union, Promise forwarding/constructor and generator producer gaps,
actual physical I/O/TTY/CRT, full Original64/SDK27/166/Agent32, source comparison
and native-only host gates still require exact-union qualification.

## Prepared controls

`build-native-sdk-actual-paths-owner` is an install-only target over canonical
cached `test.exe`. Five named Source declarations are authored: repeat/import
identity, diagnostic cleanup before publication, real GPA failure before cache
commit, ordinary A versus sole carrier cleanup B, and fresh native cleanup OOM
promotion. The controlled native callable in the last two is never invoked or
published as a successful filesystem implementation. Its sole token exercises
the actual failed factory's root retirement. Actual metadata is unknown; no
Run edge is added and no historical controller/count transfers.

`verifyActualCloudImports`, `verifyActualOwner` and `createActualSession` are
genuine-input callable profiles, not registered or discovered tests. The latter
executes the actual factory and observes its actual new AgentSession instance;
it accepts real user options, not a preconstructed session or expected fixture.
They cannot execute until their actual dependencies and Root's target/grant are
prepared. The inert original paths caller records raw function text and identity
from the real Source module; no expected/observed/baseline output exists.
