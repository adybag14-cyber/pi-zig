# Concrete remaining C3 pending-fatal producer exit

This is an unimplemented C correction proposal, separate from the inert new-function API patch.

1. Verified DA14 js_native_async_generator_drive: when native_resume returns JS_EXCEPTION with a CURRENT pending uncatchable reason, current code JS_GetException -> js_async_generator_complete -> js_async_generator_reject -> free consumes the actual event as DATA. The event must instead be held outside pending during owner/request cleanup and rethrown exactly. Neither the error name nor a bit on an input/fulfilled/rejected DATA value grants this status.
2. The drive result must report failure to js_async_generator_resume_next and both entry families. The initial/suspended-yield call from js_async_generator_next must return JS_EXCEPTION rather than its already-created Promise when an actual pending fatal exits. Cleanup must hold the reason outside pending while releasing that owned Promise.
3. The native Await reaction in js_async_generator_resolve_function must return JS_EXCEPTION to the actual VM job runner when drive has produced a current fatal; returning undefined with pending is a C callback contract violation. Rejected flagged/historical DATA with no actual pending event must retain ordinary Source semantics.
4. Owner retirement and current/queued native request ownership must be audited together. Do not strand requests, invoke user resolvers during a fatal cleanup, overwrite the first event through finalizers, or infer a new host event when processing old rejected DATA. Root must review exact request-drain/resumption policy and its finite controls before C implementation/intake; this unit does not invent that policy.
5. Causal actual-native fixture: real EventStream waiting.enqueue is a genuine native_node_function callback that returns direct GPA OutOfMemory, then a live Promise subclass throws an ordinary marker after super(executor). The holder must retain its first exact private reason, while the current C3 delivery remains a documented negative. Repeat first next, resumed next after yield, Await reaction, later diagnostic replacement, second native OOM, historical/marked lookalikes and GC/finalizer cleanup. Keep original C3 ordinary queue/return/throw/thenable observations unchanged.
